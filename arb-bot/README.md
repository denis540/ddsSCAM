# CEX ↔ DEX арбітраж з переказом і хеджем

Бот шукає різницю ціни токена між централізованими біржами і DEX, купує там, де дешевше, **переказує монети** і продає там, де дорожче. Потім повертає стейблкоїн, і цикл повторюється. Поки монети в дорозі, позиція може бути **захеджована шортом на ф'ючерсах**, тож бот заробляє на спреді, а не на вгадуванні ціни.

```
Токен дешевший на біржі:
  купити на CEX → [шорт perp] → вивести → продати на DEX → [закрити шорт] → USDT назад на біржу

Токен дешевший на DEX:
  купити на DEX → [шорт perp] → депозит на біржу → продати на CEX → [закрити шорт] → USDT назад
```

| | |
|---|---|
| Біржі | Binance, OKX, Bybit, Gate, KuCoin, Bitget (ccxt; будь-яка інша з ccxt.pro — одним рядком) |
| DEX | KyberSwap + Odos: бот бере кращий маршрут серед усіх DEX мережі |
| Мережі | Arbitrum, BSC, Base, Polygon, Optimism (додаються в конфігу) |
| Токени | вручну або автопошуком (`npm run discover`) |

## Як бот приймає рішення

1. **WebSocket-стакани** на всіх біржах.
2. **Зондування.** Для кожного токена одна котировка DEX в обидва боки. Якщо різниця з найкращою ціною на CEX ≥ `probeEdgeBps`, вмикається повний розрахунок: сітка розмірів, обидва агрегатори. Так бот тягне сотні токенів і не впирається в ліміти API.
3. **Повний розрахунок** включає глибину стакану, taker-комісію, комісію виводу саме в цій мережі, газ, повернення USDT, комісії ф'ючерсного хеджу і запас на ризик (`riskBufferBps`; з хеджем він ×0.3).
4. **Фільтри перед стартом циклу:**
   - вивід або депозит у мережі відкриті;
   - контракт збігається;
   - токена немає в чорному списку;
   - можливість тримається `confirmScans` сканувань поспіль;
   - вистачає капіталу, газу і маржі під хедж.

## Потоки і швидкість

```
 потік binance ─┐
 потік okx     ─┤  WebSocket-стакани: розбір і злиття оновлень,
 потік bybit   ─┤  знімки top-20 не частіше ніж раз на bookThrottleMs
 ...           ─┘
                ▼
 основний потік: сканування → рішення → ордери, свопи, перекази
```

- **Окремий потік на кожну біржу** (`marketDataWorkers: true`). Розбір сотень стаканів — єдина помітна робота процесора в боті, і вона більше не блокує відправку ордерів. Потік, що впав, сам перезапускається, а дані з нього тим часом не використовуються.
- **Основний потік** займається лише рішеннями й мережевими запитами. Вони асинхронні й ідуть паралельно, тож додаткові потоки тут нічого не пришвидшать: час іде на очікування відповіді біржі чи блокчейну, а не на обчислення.
- **Затримка основного потоку** показується в `heartbeat` і `/status` (`lag p99`). Норма — до 10 мс. Якщо вища, зменшіть кількість токенів або збільште `bookThrottleMs`.

## Надійність

- **Машина станів кожного циклу** пишеться на диск (`data/cycles.json`) після кожного кроку. Після перезапуску бот продовжує з того самого місця.
- **Дії з грошима не повторюються наосліп.** Перед ордером, виводом, свопом чи переказом крок позначається. Якщо процес упав посередині, бот звіряє стан з історією біржі чи мережі. Не вдалося — ставить цикл у `NEEDS_ATTENTION` і шле алерт. Мережеві помилки повторюються лише там, де це безпечно.
- **Друга нога без хеджу:** бот чекає ціну не гірше `secondLegMaxLossBps`, після `secondLegMaxWaitMin` закриває позицію. З хеджем продає одразу.
- **Хедж:** не відкрився — цикл іде без хеджу з алертом (або пропускається при `required: true`). Не закрився — бот повторює спробу, потім алерт «ВІДКРИТИЙ ШОРТ».
- **Податкові токени:** якщо отримано менше за котирування понад slippage + 2%, токен іде в чорний список.
- **Захисти:** денний ліміт збитку, ліміт помилок поспіль, `maxConcurrentCycles`, один цикл на токен. Аварійна зупинка: `touch STOP` або `/pause`.

## Запуск

```bash
cd arb-bot
npm install
cp .env.example .env               # ключі, RPC, приватний ключ гаманця
cp config.example.json config.json # біржі, мережі, ліміти, хедж
npm run discover                   # необов'язково: знайти токени автоматично
npm run dev                        # dryRun: true → paper-трейдинг
```

Продакшн: `docker compose up -d --build` (автоперезапуск, дані в `./data`).

### Telegram

`TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID` у `.env`. Бот слухається тільки цього чату.

| Команда | Що робить |
|---|---|
| `/status` | режим, біржі, активні цикли, PnL за день |
| `/opps` | поточні можливості |
| `/cycles` | активні цикли і ті, що потребують уваги |
| `/pnl` | 24 год / 7 днів, live і paper окремо |
| `/pause` | зупинити нові цикли |
| `/resume` | відновити |

### Paper-трейдинг

У `dryRun` кожна можливість «виконується» уявно: через `paperTransferMin` хвилин бот оцінює другу ногу за **реальними** цінами того моменту і пише результат у `data/journal.csv` (окремо результат без хеджу і з хеджем). Це чесна перевірка стратегії до того, як ризикувати грошима.

### Підготовка до LIVE

1. Окремий EVM-гаманець лише для бота: стейбли і нативна монета на газ у кожній мережі.
2. На біржах API-ключ з правами **торгівля + вивід + ф'ючерси**, прив'язаний до IP сервера. **Адреса гаманця в whitelist для виводу.**
3. USDT на спотовому рахунку кожної біржі; USDT на ф'ючерсному або unified-рахунку тих бірж, де стоїть хедж.
4. 1–2 тижні paper-трейдингу, аналіз `journal.csv`.
5. На кожній біржі один live-цикл на мінімальну суму в кожному напрямку. Тільки потім збільшувати `tradeSizesQuote`.

## Ризики

- Хедж прибирає ризик ціни, але не ризик **затримки виводу**: біржа може тримати вивід годинами.
- **Funding** на perp-ринку зазвичай копійки за хвилини переказу, але на хайпових токенах буває екстремальний.
- **Base:** стейбл у ланцюгу USDC, а на біржі USDT. Бот вважає їх 1:1 і не повертає кошти автоматично.
- **Автопошук:** токени з нього перевіряйте вибірково, особливо великі угоди.
