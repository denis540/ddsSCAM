# CEX ↔ DEX арбітраж з переказом

Бот шукає різницю ціни токена між централізованими біржами і DEX, купує там, де дешевше, **переказує монети** і продає там, де дорожче. Потім повертає стейблкоїн назад, і цикл повторюється.

```
Токен дешевший на біржі:
  купити на CEX → вивести на гаманець → продати на DEX → USDT назад на біржу

Токен дешевший на DEX:
  купити на DEX → депозит на біржу → продати на CEX → USDT назад на гаманець
```

- **Біржі:** Binance, OKX, Bybit, Gate, KuCoin, Bitget (через ccxt; можна додати будь-яку з ccxt.pro).
- **DEX:** агрегатор KyberSwap, тобто найкращий маршрут серед усіх DEX мережі (Uniswap, PancakeSwap, Curve, Camelot…).
- **Мережі:** Arbitrum і BSC у прикладі; додаються в `config.json`.

## Що бот враховує

- реальну глибину стакану на кожній біржі (WebSocket);
- taker-комісію біржі, **комісію виводу саме для цієї мережі**, газ свопу і переказу, вартість повернення USDT;
- `riskBufferBps` — запас на рух ціни, поки монети в дорозі;
- **чи відкриті депозит і вивід** у цій мережі на цій біржі (перевірка кожні 3 хв). Більшість «величезних спредів» виникає саме тоді, коли біржа закрила вивід, і бот такі пари пропускає;
- **адресу контракту.** Якщо біржа її повідомляє і вона не збігається з вашою, пара блокується, бо однаковий тікер ще не означає той самий токен;
- що можливість тримається `confirmScans` сканувань поспіль.

## Надійність

- Кожен цикл — це машина станів, яка **зберігається на диск** (`data/cycles.json`) після кожного кроку. Після перезапуску бот продовжує з того самого місця.
- Перед кожною дією, що рухає гроші, крок позначається. Якщо процес упав посередині, дія **не повторюється наосліп**: бот шукає її в історії біржі чи мережі, а якщо не знаходить — ставить цикл у `NEEDS_ATTENTION` і шле алерт.
- **Захист другої ноги.** Якщо поки монети йшли ціна впала більше ніж на `secondLegMaxLossBps`, бот чекає до `secondLegMaxWaitMin` хвилин, потім закриває позицію, щоб не тримати ризик.
- Вивід, який довго не доходить, дає алерт. Вивід, скасований біржею, зупиняє цикл з алертом.
- На OKX, Bybit і KuCoin бот сам переводить кошти між рахунками funding і trading.
- Захисти: денний ліміт збитку, ліміт помилок поспіль, `maxConcurrentCycles`, один активний цикл на токен, перевірка балансу газу. Аварійна зупинка: `touch STOP`.

## Запуск

```bash
cd arb-bot
npm install
cp .env.example .env               # ключі, RPC, приватний ключ гаманця
cp config.example.json config.json # біржі, мережі, токени, ліміти
npm run dev                        # dryRun: true — лише показує можливості
```

Продакшн: `npm run build && npm start` (краще під `pm2` або systemd з автоперезапуском).

### Підготовка до LIVE

1. Окремий EVM-гаманець лише для бота: стейбли і трохи нативної монети на газ (ETH на Arbitrum, BNB на BSC).
2. На кожній біржі API-ключ з правами **торгівля + вивід**, прив'язаний до IP сервера, і **адреса гаманця бота в whitelist для виводу**. Без whitelist OKX, Bybit і KuCoin не дадуть виводити через API.
3. USDT на спотовому рахунку кожної біржі.
4. 1–2 тижні у `dryRun`, дивитися на `OPPORTUNITY` в лозі. Потім LIVE з малими `tradeSizesQuote`.

### Додати токен

```json
{ "symbol": "PENDLE", "chain": "arbitrum", "address": "0x0c880f6761F1af8d9Aa9C466984b80DAb9a8c9e8", "decimals": 18 }
```
Адресу брати тільки з офіційного джерела (CoinGecko → Contract, сайт проєкту).

## Ризики, які варто розуміти

- **Час у дорозі.** Вивід з біржі займає від 1 до 30+ хвилин, і за цей час ціна може піти проти вас. Тому мінімальний поріг за замовчуванням 0.8% після всіх витрат.
- **Затримки виводу.** Біржа може затримати вивід (перевірка, ручне підтвердження великих сум).
- **Нестача капіталу.** Капітал має бути на обох боках, інакше цикл не стартує.
- **Тестовий прогін.** Тестуйте на малих сумах: помилка в адресі токена чи мережі коштує всієї суми.
