# DEX ↔ CEX арбітражний бот

Uniswap V3 (Arbitrum) ↔ Binance Spot, пара за замовчуванням **WETH/USDC ↔ ETHUSDC**.
TypeScript / Node.js 20+.

## Як працює

1. **Ціни CEX** — WebSocket `depth20@100ms` Binance (оновлення кожні 100 мс), авто-реконект, захист від «мертвого» сокета, книга застаріла > `CEX_STALE_MS` → торгівля блокується.
2. **Ціни DEX** — на кожному новому блоці (і при русі ціни на CEX > `REEVAL_ON_CEX_MOVE_BPS`) бот котирує сітку розмірів через Uniswap QuoterV2 в обидва боки. Усі `eth_call` йдуть **одним batch-запитом**.
3. **Оцінка** — проходить по реальній глибині книги CEX, враховує taker-комісію, комісію пулу, газ і крок лоту; вибирає розмір з максимальним чистим прибутком ≥ `MIN_PROFIT_USD` і ≥ `MIN_PROFIT_BPS`.
4. **Виконання (інвентарна модель)** — гроші лежать на обох майданчиках, переказів між ними під час угоди немає:
   - спочатку DEX-своп з `amountOutMinimum` і дедлайном → або виконається не гірше прийнятої ціни, або ревертне (позиції немає, втрачено лише газ);
   - потім хедж на Binance рівно на фактично отриману кількість (MARKET, ідемпотентний `clientOrderId`; при таймауті бот *перевіряє статус ордера*, а не повторює наосліп — без подвійного виконання).
5. **Ризик** — денний ліміт збитку, ліміт послідовних помилок, мінімальні резерви, кулдаун, kill-switch (файл `STOP` у папці бота), зупинка з алертом у Telegram, якщо хедж не вдався.

## Запуск

```bash
cd arb-bot
npm install
cp .env.example .env     # заповнити
npm run dev              # DRY_RUN=true — лише логує можливості
# продакшн:
npm run build && npm start
```

Перед LIVE:
- API-ключ Binance **без права виводу**, з whitelist IP сервера.
- Окремий гаманець лише під бота; на ньому WETH, USDC і трохи ETH на газ.
- Інвентар з обох боків (USDC + ETH на Binance, WETH + USDC в гаманці).
- Тиждень на `DRY_RUN=true`, подивитись на лог `OPPORTUNITY`/`heartbeat`, потім LIVE з малим `MAX_TRADE_QUOTE`.
- Аварійна зупинка: `touch STOP` або `Ctrl+C` (бот дочекається завершення хеджу).

Тести: `npm test`.

## Від чого реально залежить швидкість

| Фактор | Вплив |
|---|---|
| Сервер поруч з Binance (AWS Tokyo `ap-northeast-1`) | десятки мс |
| Власна нода / платний RPC з WS замість публічного | 50–300 мс |
| Мова (Node vs C++) | < 1 мс на цикл |

## Що можна додати далі

- Binance WebSocket API для ордерів (ще -10–30 мс до REST).
- Локальна математика пулу V3 (sqrtPrice + тіки) замість QuoterV2 — котирування без RPC.
- Кілька пар / пулів / мереж (Base, BSC) і кілька CEX (OKX, Bybit).
- Авто-ребаланс інвентаря між біржею та гаманцем.
- На Ethereum mainnet — приватна відправка через Flashbots (захист від сендвічів). На Arbitrum публічного мемпулу немає.
