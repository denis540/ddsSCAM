# Funding Arbitrage Bot (Node.js)

Бот для дельта-нейтрального арбітражу фандінгу між криптобіржами (USDT-M перпетуали) на базі [ccxt](https://github.com/ccxt/ccxt).

## Як це працює

1. Кожні `SCAN_INTERVAL_SEC` секунд бот бере ставки фандінгу всіх USDT-перпетуалів з усіх бірж.
2. Ставки **нормалізуються до години**, бо інтервали виплат різні (Binance/OKX здебільшого 8h, частина пар 4h/1h, у Bybit/Bitget бувають 1h–4h).
3. Для кожної монети, що є на ≥2 біржах, шукається пара:
   - **SHORT** там, де фандінг вищий (шорт отримує позитивний фандінг),
   - **LONG** там, де нижчий (лонг отримує негативний фандінг).
4. Вхід лише якщо: спред ≥ `MIN_SPREAD_8H_PCT`, очікуваний профіт за `HOLD_HOURS_ESTIMATE` годин мінус 4 тейкер-комісії ≥ `MIN_EXPECTED_PROFIT_PCT`, різниця цін між біржами (basis) не гірша за `MAX_ENTRY_BASIS_PCT`, а в стакані вистачає ліквідності в межах `MAX_SLIPPAGE_PCT`.
5. Обсяг підбирається однаковим у базовій монеті з урахуванням `contractSize` і кроку лота на обох біржах.
6. Обидві ноги відкриваються **паралельно** ринковими ордерами. Якщо одна не виконалась — інша одразу закривається (`reduceOnly`). Часткові виконання вирівнюються.
7. Пара закривається, коли спред падає нижче `EXIT_SPREAD_8H_PCT`, минув `MAX_HOLD_HOURS` або будь-яка нога ближче до ліквідації, ніж `LIQ_BUFFER_PCT`.

Стан (відкриті/закриті позиції, нарахований фандінг, PnL) зберігається в `data/state.json`, тож після перезапуску бот продовжує супровід позицій.

## Запуск

```bash
cd funding-bot
npm install
cp .env.example .env      # відредагуйте налаштування

npm run scan              # тільки показує таблицю можливостей, нічого не торгує
npm start                 # MODE=paper — симуляція з обліком фандінгу і PnL
# MODE=live у .env — реальна торгівля
npm test
```

## Рекомендований порядок

1. `npm run scan` — подивитися, які спреди реально бувають.
2. Кілька днів у `MODE=paper` — перевірити, чи покриває фандінг комісії та спред стакану.
3. `MODE=live` з малим `POSITION_USDT` (10–20 USDT) і `MAX_POSITIONS=1`.

## Важливо про ризики

- **Ставка фандінгу змінюється.** Те, що зараз +0.1%, через 8 годин може бути від'ємним. Бот бачить лише поточну (прогнозну) ставку.
- **Комісії:** 4 тейкер-угоди (≈0.2% номіналу при 0.05%) — одна виплата фандінгу їх часто не покриває, тому і є `HOLD_HOURS_ESTIMATE`.
- **Ліквідація однієї ноги.** При сильному русі ціни прибуток на одній біржі не рятує від ліквідації на іншій — маржа на біржах окрема. Тримайте низьке плече та запас USDT на обох біржах. Переказ маржі між біржами бот не робить.
- **Basis-ризик:** ціни на біржах можуть розходитись, і при закритті можна втратити більше, ніж зароблено на фандінгу.
- У live-режимі нарахований фандінг у логах — **оцінка**; точні суми дивіться в історії на біржі.
- Перед live перевірте на кожній біржі: one-way position mode (не hedge mode), USDT-M ф'ючерсний акаунт, дозволи API-ключа **без виведення коштів**, IP whitelist.
- Ctrl+C зупиняє бот, але **не закриває** відкриті позиції.

Код наданий «як є»; торгівля з плечем може призвести до втрати коштів.
